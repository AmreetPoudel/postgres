# 3.4 — pgBackRest: Production Backup

**Phase**: 3 — Backup, Recovery & PITR
**Est. reading time**: 25 min

---

## Why pgBackRest Over pg_basebackup

pg_basebackup is fine for simple setups and quick standby creation. For production backup strategy, it falls short:

| Feature | pg_basebackup | pgBackRest |
|---|---|---|
| Full backup | Yes | Yes |
| Differential backup | No | Yes |
| Incremental backup | No | Yes |
| Parallel backup | No | Yes (multiple processes) |
| Parallel restore | No | Yes |
| Built-in archiving | No | Yes |
| Retention policies | No | Yes |
| Backup verification | No | Yes (`--verify`) |
| Remote backup | Limited | Yes (via SSH or TLS) |
| Cloud storage (S3, GCS, Azure) | No | Yes |
| Encryption | No | Yes |

---

## How pgBackRest Works

```
PostgreSQL server
    │
    ├── WAL archiving → pgBackRest archive-push → backup repository
    │
    └── Base backup  → pgBackRest backup       → backup repository

Backup repository:
    /backup/pgbackrest/
    ├── archive/          ← WAL segments
    │   └── main/
    │       └── 16-1/
    │           └── 000000010000000000000001.gz
    └── backup/           ← base + incremental backups
        └── main/
            ├── 20261001-020000F/    ← full backup
            ├── 20261002-020000D/    ← differential
            └── 20261003-020000I/    ← incremental
```

## Configuration

pgBackRest uses `/etc/pgbackrest/pgbackrest.conf` (or `/etc/pgbackrest.conf`):

```ini
[global]
# Repository location (local)
repo1-path=/var/lib/pgbackrest

# Or S3:
# repo1-type=s3
# repo1-s3-bucket=my-pg-backups
# repo1-s3-endpoint=s3.amazonaws.com
# repo1-s3-region=us-east-1
# repo1-s3-key=AKIAIOSFODNN7EXAMPLE
# repo1-s3-key-secret=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY

# Retention
repo1-retention-full=7          # keep 7 full backups
repo1-retention-diff=14         # keep 14 differential backups

# Encryption (optional but recommended for S3)
# repo1-cipher-type=aes-256-cbc
# repo1-cipher-pass=strongpassphrase

# Logging
log-level-console=info
log-level-file=detail
log-path=/var/log/pgbackrest

[global:archive-push]
compress-level=3                # compression level for WAL archiving

[main]
# Stanza name is 'main' (can be anything, matches PostgreSQL cluster)
pg1-path=/var/lib/postgresql/16/main
pg1-port=5432
pg1-user=postgres
```

---

## Creating the Stanza

A "stanza" is pgBackRest's term for a PostgreSQL cluster configuration:

```bash
# Create the stanza (initializes backup repository)
pgbackrest --stanza=main stanza-create

# Verify everything is configured correctly
pgbackrest --stanza=main check
```

---

## Configure PostgreSQL to Use pgBackRest

```
# postgresql.conf
archive_mode = on
archive_command = 'pgbackrest --stanza=main archive-push %p'
archive_timeout = 300
wal_level = replica
```

```bash
# Reload PostgreSQL
pg_ctl reload -D /var/lib/postgresql/16/main

# Test archiving works
pgbackrest --stanza=main check
```

## Taking Backups

```bash
# Full backup
pgbackrest --stanza=main --type=full backup

# Differential backup (changes since last full)
pgbackrest --stanza=main --type=diff backup

# Incremental backup (changes since last full/diff/incr)
pgbackrest --stanza=main --type=incr backup

# With progress display
pgbackrest --stanza=main --type=full backup --log-level-console=detail

# List all backups
pgbackrest --stanza=main info
```

## Restoring with pgBackRest

### Full restore (restore latest backup):

```bash
# 1. Stop PostgreSQL
pg_ctl stop -m fast -D /var/lib/postgresql/16/main

# 2. Clear data directory (pgBackRest will not restore over existing files)
rm -rf /var/lib/postgresql/16/main/*

# 3. Restore
pgbackrest --stanza=main restore

# 4. Start PostgreSQL (applies WAL from archive to reach consistent state)
pg_ctl start -D /var/lib/postgresql/16/main
```

### PITR restore (restore to specific time):

```bash
# Restore to specific time
pgbackrest --stanza=main restore \
  --type=time \
  --target="2026-10-07 09:59:00" \
  --target-action=promote

pg_ctl start -D /var/lib/postgresql/16/main
```

### Restore specific backup:

```bash
# List backups
pgbackrest --stanza=main info

# Restore a specific backup (by its label)
pgbackrest --stanza=main restore \
  --set=20261001-020000F
```

## Backup Schedule Recommendation

```bash
# Full backup: weekly (Sunday 1 AM)
0 1 * * 0 pgbackrest --stanza=main --type=full backup >> /var/log/pgbackrest/cron.log 2>&1

# Differential backup: daily (2 AM, Mon-Sat)
0 2 * * 1-6 pgbackrest --stanza=main --type=diff backup >> /var/log/pgbackrest/cron.log 2>&1
```

With this schedule, worst case restore time = full backup + 1 differential backup. Both are fast with pgBackRest's parallel restore.

---

## Verifying Backups

```bash
# Verify backup integrity (reads all files, checks checksums)
pgbackrest --stanza=main verify

# Verify a specific backup
pgbackrest --stanza=main verify --set=20261001-020000F
```

Run this after every backup in your cron script.

## pgBackRest with a Remote Repository

If the backup repository is on a different server:

```ini
# /etc/pgbackrest/pgbackrest.conf (on PostgreSQL server)
[global]
repo1-host=backup-server
repo1-host-user=pgbackrest
repo1-path=/var/lib/pgbackrest

[main]
pg1-path=/var/lib/postgresql/16/main
```

```ini
# /etc/pgbackrest/pgbackrest.conf (on backup server)
[global]
repo1-path=/var/lib/pgbackrest

[main]
pg1-path=/var/lib/postgresql/16/main
pg1-host=postgres-server
pg1-host-user=postgres
```

Requires SSH key-based authentication between servers.

---

## Parallel Backup and Restore

pgBackRest can use multiple processes:

```ini
[global]
# Number of processes for backup/restore
process-max=4     # use 4 parallel processes

# Or specify per operation:
# pgbackrest --stanza=main --process-max=8 restore
```

On a 16-core server with fast NVMe, using 8 processes can reduce restore time by 4-8×.
