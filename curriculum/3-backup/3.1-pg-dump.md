# 3.1 — pg_dump & pg_dumpall: Logical Backups

**Phase**: 3 — Backup, Recovery & PITR
**Est. reading time**: 20 min

---

## Logical vs Physical Backup

There are two completely different types of PostgreSQL backups:

| Type | Tool | What it backs up | Restore to different PG version? |
|---|---|---|---|
| **Logical** | pg_dump, pg_dumpall | SQL statements to recreate data | Yes |
| **Physical** | pg_basebackup, pgBackRest | Raw data files, byte-for-byte copy | No (same major version only) |

**When to use logical (pg_dump):**
- Migrating to a different PostgreSQL major version (e.g., PG14 → PG16)
- Migrating to different OS/architecture
- Selectively backing up one table or schema
- Export data for archival or sharing

**When to use physical (pg_basebackup / pgBackRest):**
- Production backup strategy (much faster, supports PITR)
- Disaster recovery
- Setting up standbys

## pg_dump — Single Database Backup

```bash
# Basic dump (plain SQL format)
pg_dump -U postgres -d mydb > mydb_backup.sql

# Restore:
psql -U postgres -d mydb_restored < mydb_backup.sql
```

**The four output formats:**

| Format | Flag | Good for |
|---|---|---|
| plain | `-F p` (default) | Human-readable SQL, easy to inspect |
| custom | `-F c` | Best for restore: compressed, selective restore |
| directory | `-F d` | Parallel dump/restore with multiple files |
| tar | `-F t` | Single compressed archive |

**Custom format is what you want for production backups:**
```bash
# Compressed custom format
pg_dump -U postgres -d mydb -F c -f mydb_backup.dump

# Restore from custom format
pg_restore -U postgres -d mydb_restored mydb_backup.dump

# Selective restore: only restore one table
pg_restore -U postgres -d mydb_restored -t orders mydb_backup.dump
```

## pg_dump Options You Need to Know

```bash
pg_dump \
  -U postgres \           # connect as this user
  -h localhost \          # host
  -p 5432 \              # port
  -d mydb \              # database
  -F c \                 # custom format
  -Z 9 \                 # compression level (0-9, 9=max)
  -j 4 \                 # parallel jobs (directory format only)
  --no-password \        # don't prompt for password
  -f mydb_$(date +%Y%m%d).dump

# Schema only (no data)
pg_dump -U postgres -d mydb -s -F c -f mydb_schema.dump

# Data only (no schema)
pg_dump -U postgres -d mydb -a -F c -f mydb_data.dump

# Specific tables only
pg_dump -U postgres -d mydb -t orders -t customers -F c -f mydb_tables.dump

# Exclude a table
pg_dump -U postgres -d mydb -T logs -F c -f mydb_nologs.dump

# Verbose (shows progress)
pg_dump -U postgres -d mydb -F c -v -f mydb_backup.dump
```

## pg_dumpall — Everything in the Cluster

`pg_dump` only dumps one database. pg_dumpall dumps:
- All databases
- Roles (users)
- Tablespaces
- Global configuration

```bash
# Full cluster dump (plain SQL only, no custom format)
pg_dumpall -U postgres > cluster_backup.sql

# Roles only (no database data)
pg_dumpall -U postgres --roles-only > roles.sql

# Schema only across all databases
pg_dumpall -U postgres -s > cluster_schema.sql

# Restore
psql -U postgres < cluster_backup.sql
```

## Automating pg_dump

**Simple cron script:**
```bash
#!/bin/bash
# /usr/local/bin/pg_backup.sh

BACKUP_DIR="/backup/postgres"
DATE=$(date +%Y%m%d_%H%M%S)
DB="mydb"
USER="postgres"
KEEP_DAYS=7

mkdir -p $BACKUP_DIR

# Dump
pg_dump -U $USER -d $DB -F c -Z 9 \
  -f "$BACKUP_DIR/${DB}_${DATE}.dump" \
  && echo "Backup succeeded: ${DB}_${DATE}.dump" \
  || { echo "Backup FAILED for $DB"; exit 1; }

# Cleanup old backups
find $BACKUP_DIR -name "${DB}_*.dump" -mtime +$KEEP_DAYS -delete

echo "Backup complete. Size: $(du -sh $BACKUP_DIR/${DB}_${DATE}.dump | cut -f1)"
```

```
# crontab -e
0 2 * * * /usr/local/bin/pg_backup.sh >> /var/log/pg_backup.log 2>&1
```

## Verifying Backups

**Always verify your backups.** A backup you can't restore is not a backup.

```bash
# Test restore to a temp database
createdb -U postgres mydb_test
pg_restore -U postgres -d mydb_test mydb_backup.dump
# Check row counts, spot check data
psql -U postgres -d mydb_test -c "SELECT count(*) FROM orders;"
dropdb -U postgres mydb_test
```

**Check backup integrity without restoring:**
```bash
# pg_restore with list only — reads the archive header, no actual restore
pg_restore --list mydb_backup.dump | head -20
```

## Limitations of pg_dump

1. **Not a point-in-time backup**: Dump captures a consistent snapshot but only at the moment of the dump. Data changed after the dump starts is not included.

2. **Slow on large databases**: Dumping 1TB takes hours. Physical backup is much faster.

3. **No PITR capability**: Can't restore to "2 minutes before the dump started."

4. **Doesn't back up WAL**: You can't replay WAL onto a pg_dump restore.

5. **For production DR, use pgBackRest** (Phase 3.4). pg_dump is a tool for specific use cases, not your primary backup strategy.

## pg_dump with Password

```bash
# Using .pgpass file (recommended)
cat ~/.pgpass
# hostname:port:database:username:password
# localhost:5432:mydb:postgres:mysecretpass

chmod 600 ~/.pgpass

# Or use environment variable
export PGPASSWORD='mysecretpass'
pg_dump -U postgres -d mydb -F c -f mydb.dump
unset PGPASSWORD

# Or connection string
pg_dump "postgresql://postgres:mysecretpass@localhost/mydb" -F c -f mydb.dump
```
