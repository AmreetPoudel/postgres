# 2.3 — SSL/TLS: Encrypting PostgreSQL Connections

**Phase**: 2 — Configuration & Tuning
**Est. reading time**: 15 min

---

## Why SSL Matters

Without SSL, everything between client and server is plaintext: passwords, query text, result data. Anyone who can sniff the network traffic can see it all.

With SSL: encrypted tunnel. Even if traffic is intercepted, it's unreadable.

**Required for**: Any PostgreSQL instance accessible over a network, especially cloud or multi-datacenter setups.

---

## Enabling SSL in PostgreSQL

```bash
# Generate self-signed certificate (for internal use / testing)
openssl req -new -x509 -days 365 -nodes \
  -out /etc/ssl/certs/postgres.crt \
  -keyout /etc/ssl/private/postgres.key \
  -subj "/CN=my-postgres-server"

chmod 600 /etc/ssl/private/postgres.key
chown postgres:postgres /etc/ssl/private/postgres.key /etc/ssl/certs/postgres.crt
```

```
# postgresql.conf
ssl = on
ssl_cert_file = '/etc/ssl/certs/postgres.crt'
ssl_key_file = '/etc/ssl/private/postgres.key'

# Optional: CA certificate to verify client certs
ssl_ca_file = '/etc/ssl/certs/ca.crt'

# TLS version (require TLS 1.2+)
ssl_min_protocol_version = 'TLSv1.2'

# Cipher suites (restrict to strong ones)
ssl_ciphers = 'HIGH:MEDIUM:+3DES:!aNULL'
```

Restart required after enabling SSL.

## Requiring SSL in pg_hba.conf

```
# Only allow SSL connections
hostssl   all   all   10.0.0.0/24   scram-sha-256

# Block non-SSL connections
hostnossl all   all   10.0.0.0/24   reject
```

Or allow both but prefer SSL (less strict):
```
host      all   all   10.0.0.0/24   scram-sha-256
```

## Client-Side SSL Modes

When connecting with psql or an application:

```bash
# Require SSL
psql "postgresql://user@host/db?sslmode=require"

# Verify server certificate (trusted CA)
psql "postgresql://user@host/db?sslmode=verify-ca&sslrootcert=ca.crt"

# Verify cert AND hostname (strongest)
psql "postgresql://user@host/db?sslmode=verify-full&sslrootcert=ca.crt"
```

**SSL modes:**

| Mode | Encrypt | Verify CA | Verify hostname |
|---|---|---|---|
| `disable` | No | No | No |
| `allow` | Maybe | No | No |
| `prefer` | If available | No | No |
| `require` | Yes | No | No |
| `verify-ca` | Yes | Yes | No |
| `verify-full` | Yes | Yes | Yes |

**Production recommendation**: `verify-full` with a proper CA (self-signed CA for internal, Let's Encrypt or commercial CA for external-facing). At minimum `require` so traffic is encrypted.

## SSL Certificate from Let's Encrypt (for internet-facing)

```bash
# Install certbot
apt install certbot

# Get certificate
certbot certonly --standalone -d your-postgres-domain.com

# Certificate files go to:
# /etc/letsencrypt/live/your-postgres-domain.com/fullchain.pem
# /etc/letsencrypt/live/your-postgres-domain.com/privkey.pem

# Link to PostgreSQL
ln -s /etc/letsencrypt/live/domain.com/fullchain.pem /etc/ssl/certs/postgres.crt
ln -s /etc/letsencrypt/live/domain.com/privkey.pem /etc/ssl/private/postgres.key
```

**Auto-renewal**: certbot installs a cron job. After renewal, reload PostgreSQL:
```bash
# /etc/letsencrypt/renewal-hooks/post/postgresql.sh
#!/bin/bash
pg_ctl reload -D /var/lib/postgresql/16/main
```

## Client Certificate Authentication

For even stronger security: client must present a certificate, not just a password.

```
# pg_hba.conf
hostssl   all   myapp   10.0.0.0/24   cert
```

Client connects with:
```bash
psql "postgresql://myapp@host/db?sslmode=verify-full&sslcert=client.crt&sslkey=client.key&sslrootcert=ca.crt"
```

The username in the certificate's CN field must match the PostgreSQL role. No password needed.

**When to use**: High-security environments, service-to-service authentication where you don't want to manage passwords.

## Checking SSL Status

```sql
-- Is SSL on?
SHOW ssl;

-- Current connection SSL info
SELECT ssl, cipher, bits, client_dn
FROM pg_stat_ssl
WHERE pid = pg_backend_pid();

-- All SSL-connected sessions
SELECT pid, ssl, cipher, bits, client_addr
FROM pg_stat_ssl s
JOIN pg_stat_activity a USING (pid);
```

## Performance Impact of SSL

SSL adds CPU overhead for encryption/decryption. On modern hardware with AES-NI acceleration (all modern CPUs), this is typically 1-3% overhead. Negligible.

```bash
# Check if AES-NI is available
grep aes /proc/cpuinfo | head -1
```

Use AES-128-GCM or AES-256-GCM ciphers for maximum hardware acceleration:
```
ssl_ciphers = 'ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384'
```
