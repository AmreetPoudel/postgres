## The Core Principle

> Monitoring is only useful if you understand what you're measuring.

Every metric in Grafana comes from a `pg_stat_*` view. If you don't know what `pg_stat_bgwriter.checkpoints_req` means, the dashboard panel is just a number. That's why we learn internals first.

---

## The Stack

```
PostgreSQL 16
    │  (metrics live in pg_stat_* views)
    ▼
postgres_exporter   ← translates SQL → Prometheus format
    │  (scrape interval: 15s default, tune per metric)
    ▼
Prometheus          ← stores time-series, evaluates alert rules
    │
    ▼
Grafana             ← dashboards, correlate with OS metrics
    │
    ├── node_exporter (OS: disk await, cpu, memory, swap)
    └── postgres_exporter (PG: connections, cache hit, WAL, locks, vacuum)
```

**Key insight for research**: Your parameter experiments will use Grafana to compare before/after. You need to be able to say "after increasing shared_buffers from 2GB to 8GB, cache hit rate went from 94% to 99.2% and read latency dropped 40%." That's a publishable finding.

## Critical Metrics to Track (With Source Views)

### Connections & Sessions
| Metric | Source | Alert threshold |
|--------|--------|----------------|
| Active connections | `pg_stat_activity` | > 80% of max_connections |
| Idle connections | `pg_stat_activity WHERE state='idle'` | > 50% (indicates pooling needed) |
| Waiting on locks | `pg_stat_activity WHERE wait_event_type='Lock'` | Any > 30s |
| Long-running queries | `pg_stat_activity` | Any > 5min (tune to workload) |

### Cache & I/O
| Metric | Source | Alert threshold |
|--------|--------|----------------|
| Buffer hit rate | `pg_stat_database` | < 99% (investigate) / < 95% (page) |
| Blocks read from disk | `pg_stat_database.blks_read` | Sudden spike |
| Temp files created | `pg_stat_database.temp_files` | Any (means work_mem too low) |

### WAL & Checkpoints
| Metric | Source | Alert threshold |
|--------|--------|----------------|
| Checkpoint frequency | `pg_stat_bgwriter` | checkpoints_req >> checkpoints_timed |
| Checkpoint write time | `pg_stat_bgwriter.checkpoint_write_time` | > 30s |
| WAL generation rate | `pg_current_wal_lsn()` over time | Workload-dependent baseline |
| Archiving lag | `pg_stat_archiver` | last_failed_time advancing |

### Replication (Phase 4+)
| Metric | Source | Alert threshold |
|--------|--------|----------------|
| Replication lag (bytes) | `pg_stat_replication` | > 100MB (sync) / tune for async |
| Replication lag (time) | `pg_replication_slots` | > 30s |
| Slot retained WAL | `pg_replication_slots.pg_wal_lsn_diff` | Growing without bound = danger |

### VACUUM & Bloat
| Metric | Source | Alert threshold |
|--------|--------|----------------|
| Dead tuple ratio | `pg_stat_user_tables` | n_dead_tup / n_live_tup > 20% |
| Last autovacuum | `pg_stat_user_tables.last_autovacuum` | > 1 day on active tables |
| Txn ID age | `pg_database.datfrozenxid` | > 1.5 billion (wraparound risk) |
| Table bloat | `pg_relation_size` vs `pg_total_relation_size` | Ratio > 1.5x |

### Locks
| Metric | Source | Alert threshold |
|--------|--------|----------------|
| Lock waits | `pg_locks JOIN pg_stat_activity` | Any chain > 3 deep |
| Deadlocks | `pg_stat_database.deadlocks` | Any |

## Setup Steps (Do This When We Reach Phase 2.8)

### 1. postgres_exporter

```bash
# Install (adjust version)
wget https://github.com/prometheus-community/postgres_exporter/releases/download/v0.15.0/postgres_exporter-0.15.0.linux-amd64.tar.gz

# Create a dedicated monitoring user in PostgreSQL (minimal permissions)
psql -U postgres << 'EOF'
CREATE USER monitoring WITH PASSWORD 'monitorpass';
GRANT pg_monitor TO monitoring;    -- PG10+ built-in role, read-only access to stats
EOF

# Run with connection string
./postgres_exporter \
  --web.listen-address=":9187" \
  --log.level=info
# Set DATA_SOURCE_NAME env var for connection
```

### 2. Prometheus scrape config

```yaml
# prometheus.yml
scrape_configs:
  - job_name: 'postgresql'
    static_configs:
      - targets: ['localhost:9187']
    scrape_interval: 15s

  - job_name: 'node'
    static_configs:
      - targets: ['localhost:9100']   # node_exporter for OS metrics
    scrape_interval: 15s
```

### 3. Key Alert Rules

```yaml
# postgres_alerts.yml
groups:
  - name: postgresql
    rules:
      - alert: PostgreSQLDown
        expr: pg_up == 0
        for: 1m
        labels:
          severity: critical

      - alert: PostgreSQLHighConnections
        expr: pg_stat_database_numbackends / pg_settings_max_connections > 0.8
        for: 5m
        labels:
          severity: warning

      - alert: PostgreSQLLowCacheHitRate
        expr: |
          rate(pg_stat_database_blks_hit[5m]) /
          (rate(pg_stat_database_blks_hit[5m]) + rate(pg_stat_database_blks_read[5m])) < 0.99
        for: 10m
        labels:
          severity: warning

      - alert: PostgreSQLReplicationLagHigh
        expr: pg_replication_lag > 30
        for: 5m
        labels:
          severity: critical

      - alert: PostgreSQLDeadlockDetected
        expr: increase(pg_stat_database_deadlocks[5m]) > 0
        labels:
          severity: warning

      - alert: PostgreSQLAutovacuumNotRunning
        expr: |
          time() - pg_stat_user_tables_last_autovacuum > 86400
          AND pg_stat_user_tables_n_live_tup > 1000
        for: 1h
        labels:
          severity: warning
```
