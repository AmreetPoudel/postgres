# 5.4 — HAProxy & VIP: Routing Connections to the Right Node

**Phase**: 5 — HA & Failover
**Est. reading time**: 20 min

---

## The Problem

After failover, the primary is on a different server. Your application has a connection string pointing to a hostname or IP. How does it automatically connect to the new primary?

Two solutions:
1. **Virtual IP (VIP)**: A floating IP address that moves to the new primary
2. **HAProxy**: A load balancer that routes to the current primary based on health checks

Most production setups use both: HAProxy for connection management + keepalived for VIP.

---

## HAProxy Configuration

HAProxy uses Patroni's REST API (`/primary`, `/replica`) to determine which node is healthy and in which role.

```
# /etc/haproxy/haproxy.cfg

global
    maxconn 200
    log /dev/log local0
    chroot /var/lib/haproxy
    user haproxy
    group haproxy
    daemon

defaults
    log global
    mode tcp
    option tcplog
    option dontlognull
    timeout connect 5s
    timeout client 30m
    timeout server 30m
    option clitcpka

# Statistics page
listen stats
    bind *:7000
    stats enable
    stats uri /
    stats refresh 5s

# Primary connections (read-write): routes only to current primary
listen postgres_primary
    bind *:5000                          # apps connect here for writes
    option httpchk GET /primary         # Patroni returns 200 only if node is primary
    http-check expect status 200
    default-server inter 3s fall 3 rise 2 on-marked-down shutdown-sessions
    server pg-node1 10.0.0.10:5432 check port 8008
    server pg-node2 10.0.0.20:5432 check port 8008
    server pg-node3 10.0.0.30:5432 check port 8008

# Replica connections (read-only): load balance across all replicas
listen postgres_replicas
    bind *:5001                          # apps connect here for reads
    balance roundrobin
    option httpchk GET /replica         # Patroni returns 200 only if node is replica
    http-check expect status 200
    default-server inter 3s fall 3 rise 2 on-marked-down shutdown-sessions
    server pg-node1 10.0.0.10:5432 check port 8008
    server pg-node2 10.0.0.20:5432 check port 8008
    server pg-node3 10.0.0.30:5432 check port 8008
```

**How it works:**
- Every 3 seconds, HAProxy hits `GET /primary` on each PostgreSQL node's Patroni API
- Only the current primary returns 200 from `/primary`
- HAProxy routes write connections to port 5000 → only to the primary
- HAProxy routes read connections to port 5001 → to any replica (load balanced)

On failover: within 3 seconds, HAProxy detects the old primary is no longer `/primary`, removes it, and routes to the new primary.

## Starting HAProxy

```bash
apt install haproxy
systemctl enable haproxy
systemctl start haproxy

# Test config
haproxy -c -f /etc/haproxy/haproxy.cfg

# Check status
haproxy -f /etc/haproxy/haproxy.cfg -sf $(cat /var/run/haproxy.pid)
```

## keepalived — Virtual IP

keepalived creates a VIP that floats between servers. If the node holding the VIP goes down, another node picks it up.

**Typical use for PostgreSQL HA:**
- VIP on the HAProxy server (not on the PostgreSQL server)
- If HAProxy server fails, VIP moves to backup HAProxy server
- Applications always connect to the VIP → no DNS changes needed

```
App → VIP (e.g., 10.0.0.100) → HAProxy active → PostgreSQL primary
                                             ↑
             HAProxy backup (hot standby, VIP moves here if active fails)
```

```
# /etc/keepalived/keepalived.conf (on active HAProxy server)

vrrp_script check_haproxy {
    script "killall -0 haproxy"    # check if haproxy is running
    interval 2
    weight 2
}

vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 100
    advert_int 1

    authentication {
        auth_type PASS
        auth_pass strongpassword
    }

    virtual_ipaddress {
        10.0.0.100/24 dev eth0    # the VIP
    }

    track_script {
        check_haproxy
    }
}
```

```
# /etc/keepalived/keepalived.conf (on backup HAProxy server)
# Same but:
state BACKUP
priority 90              # lower priority than MASTER
```

```bash
apt install keepalived
systemctl enable keepalived
systemctl start keepalived

# Verify VIP is up
ip addr show eth0 | grep 10.0.0.100
```

## Application Connection Strings

With this setup, applications always connect to the VIP:

```
# Writes (primary only)
postgresql://user:pass@10.0.0.100:5000/mydb

# Reads (replicas, load balanced)
postgresql://user:pass@10.0.0.100:5001/mydb
```

Or with PgBouncer in front:
```
postgresql://user:pass@10.0.0.100:6432/mydb
```

## PgBouncer with HAProxy

The full stack:

```
Application
    ↓
VIP (keepalived): 10.0.0.100
    ↓
HAProxy port 5000 (primary) / 5001 (replicas)
    ↓
PgBouncer on each PostgreSQL node (port 6432)
    ↓
PostgreSQL (port 5432)
```

HAProxy does connection routing. PgBouncer on each node handles connection pooling. This way, even if all connections go to one PostgreSQL node, PgBouncer limits the real connections to PostgreSQL.
