# 5.3 — etcd: The Brain of Your HA Cluster

**Phase**: 5 — HA & Failover
**Est. reading time**: 15 min

---

## What etcd Does for Patroni

etcd is a distributed key-value store with strong consistency guarantees. Patroni uses it to:
1. Store cluster state (who is primary, config)
2. Manage the leader lease (primary's heartbeat)
3. Arbitrate failover decisions

If etcd is unavailable, Patroni will demote the primary (it can't renew its lease) and stop all writes until etcd is reachable again. This is a safety mechanism: it's better to be unavailable than to risk split-brain.

---

## etcd Cluster Requirements

**Always run 3+ etcd nodes for quorum.**

etcd uses the Raft consensus algorithm. To tolerate `f` failures, you need `2f+1` nodes:
- 1 node: no failure tolerance
- 3 nodes: tolerates 1 failure (quorum = 2 of 3)
- 5 nodes: tolerates 2 failures (quorum = 3 of 5)

**etcd nodes must NOT be on the same PostgreSQL servers** (preferably). If the PostgreSQL server dies and etcd is also on it, you lose both a quorum member and a database node simultaneously.

## Installing etcd

```bash
# Install on each etcd node (Debian/Ubuntu)
apt install etcd

# Or download binary
ETCD_VER=v3.5.9
curl -L https://storage.googleapis.com/etcd/${ETCD_VER}/etcd-${ETCD_VER}-linux-amd64.tar.gz \
  -o etcd.tar.gz
tar xzf etcd.tar.gz
mv etcd-*/etcd etcd-*/etcdctl /usr/local/bin/
```

## etcd Configuration

On each etcd node, create `/etc/etcd/etcd.conf`:

```yaml
# /etc/etcd/etcd.conf (on etcd node 1)

name: etcd-node1
data-dir: /var/lib/etcd

# This node's peer URL (for etcd-to-etcd communication)
listen-peer-urls: http://10.0.0.1:2380
advertise-peer-urls: http://10.0.0.1:2380

# This node's client URL (for Patroni to connect)
listen-client-urls: http://10.0.0.1:2379,http://127.0.0.1:2379
advertise-client-urls: http://10.0.0.1:2379

# Cluster membership
initial-cluster: etcd-node1=http://10.0.0.1:2380,etcd-node2=http://10.0.0.2:2380,etcd-node3=http://10.0.0.3:2380
initial-cluster-state: new    # 'new' for initial setup, 'existing' for adding to cluster
initial-cluster-token: postgres-ha-cluster

# Heartbeat and election timing
heartbeat-interval: 100       # ms between heartbeats
election-timeout: 1000        # ms before starting election if no heartbeat
```

etcd node 2 and 3: same config but with their own `name` and `listen-*-urls` / `advertise-*-urls` pointing to their own IP.

## Starting etcd

```bash
cat > /etc/systemd/system/etcd.service << 'EOF'
[Unit]
Description=etcd distributed key-value store
After=network.target

[Service]
Type=notify
ExecStart=/usr/local/bin/etcd --config-file /etc/etcd/etcd.conf
Restart=always
RestartSec=5s
LimitNOFILE=40000
User=etcd

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable etcd
systemctl start etcd
```

## Verifying etcd

```bash
# Check cluster health
etcdctl --endpoints=http://10.0.0.1:2379,http://10.0.0.2:2379,http://10.0.0.3:2379 \
  endpoint health

# See who is leader
etcdctl --endpoints=http://10.0.0.1:2379 endpoint status --write-out=table

# See Patroni's state stored in etcd
etcdctl --endpoints=http://10.0.0.1:2379 get /service/postgres-cluster/ --prefix

# Sample output:
# /service/postgres-cluster/config
# /service/postgres-cluster/initialize
# /service/postgres-cluster/leader       ← current leader name
# /service/postgres-cluster/members/pg-node1
# /service/postgres-cluster/members/pg-node2
```

## etcd TLS (Production Must-Have)

In production, etcd communication should be encrypted. This requires generating TLS certificates for each etcd node and client (Patroni).

```yaml
# etcd.conf with TLS
peer-transport-security:
  cert-file: /etc/etcd/peer.crt
  key-file: /etc/etcd/peer.key
  trusted-ca-file: /etc/etcd/ca.crt
  peer-client-cert-auth: true

client-transport-security:
  cert-file: /etc/etcd/server.crt
  key-file: /etc/etcd/server.key
  trusted-ca-file: /etc/etcd/ca.crt
  client-cert-auth: true
```

```yaml
# patroni.yml with TLS for etcd3
etcd3:
  hosts: 10.0.0.1:2379,10.0.0.2:2379,10.0.0.3:2379
  cacert: /etc/patroni/ca.crt
  cert: /etc/patroni/client.crt
  key: /etc/patroni/client.key
```

## etcd Maintenance

```bash
# Compact etcd history (reduce disk usage)
etcdctl --endpoints=http://10.0.0.1:2379 compaction \
  $(etcdctl --endpoints=http://10.0.0.1:2379 endpoint status --write-out=json | \
    python3 -c "import sys,json; print(json.load(sys.stdin)[0]['Status']['header']['revision'])")

# Defragment (reclaim space after compaction)
etcdctl --endpoints=http://10.0.0.1:2379 defrag

# Backup etcd data
etcdctl --endpoints=http://10.0.0.1:2379 snapshot save /backup/etcd-$(date +%Y%m%d).db

# Restore from backup
etcdctl snapshot restore /backup/etcd-20261001.db \
  --name etcd-node1 \
  --initial-cluster "etcd-node1=http://10.0.0.1:2380,..." \
  --initial-cluster-token postgres-ha-cluster \
  --initial-advertise-peer-urls http://10.0.0.1:2380 \
  --data-dir /var/lib/etcd-restored
```
